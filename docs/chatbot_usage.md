# RAG チャットボット 使い方マニュアル

Redmine の過去チケットを根拠に回答する社内ヘルプデスク AI (Mode C) の利用者向けマニュアル。
解決しなかった場合は、その場から Redmine にチケットとしてエスカレーションできます。

> 起動方法 (docker compose の上げ方) は README の「Mode C」セクションを参照。本マニュアルは
> 「すでに Mode C が立ち上がっている前提」での **画面操作・運用** に絞っています。

---

## 1. アクセス

ブラウザで以下を開く:

```
http://localhost:8501
```

- 既定で `8501` (環境変数 `CHATBOT_FRONTEND_PORT` で変更可)
- 同じネットワーク内の別端末から使う場合は `localhost` を該当ホストの IP / FQDN に置き換え

タイトル「🤖 Redmine ヘルプデスク Chatbot」が見えれば起動成功。

## 2. 画面構成

```
┌────────────────────┬─────────────────────────────────────────┐
│ サイドバー          │ メイン画面                              │
│                    │                                         │
│ 🔧 LLM 設定         │  チャット履歴 (吹き出し)                │
│ 👤 質問者情報       │                                         │
│ ⚙️ 管理操作         │  入力欄: 「質問を入力…」                │
│                    │                                         │
│                    │  下部に HITL ボタン:                    │
│                    │   ✅ クローズ / ✏️ 継続 / 📨 エスカレ   │
└────────────────────┴─────────────────────────────────────────┘
```

サイドバーの設定は **最初のメッセージ送信前まで** 変更可。セッション開始後はロックされる
(回答の整合性を保つため)。設定を変えたい場合は「セッションをリセット」してから。

## 3. LLM 設定

サイドバーの一番上 **「🔧 LLM 設定」** で使う LLM を選ぶ。

### 3-1. プロバイダ選択

ラジオで 2 択:

- **🦙 Ollama (ローカル)** — 既定。同じ Docker ネットワーク内の Ollama サーバーで推論。
  API キー不要。社外にデータを出さない。
- **🤖 OpenAI** — OpenAI API (または OpenAI 互換 API) で推論。API キーが必要。

### 3-2. Ollama を選んだとき

- **Ollama モデル** ドロップダウン:
  - `✅` マーク付き = 既に Ollama サーバーに `pull` 済 (即使える)
  - マーク無し + `(未 pull)` = 候補リストにはあるがまだ pull されていない (使うには
    別途 `docker exec redmine-ollama ollama pull <model名>` が必要)
  - 既定モデルは環境変数 `OLLAMA_LLM_MODEL` (例: `qwen2.5:7b`)

未 pull のモデルを選んで質問すると「AI 呼出失敗」になります。✅ のあるモデルを選ぶか、
先に pull するか、後述の OpenAI に切り替えてください。

### 3-3. OpenAI を選んだとき

3 つの入力欄が出る:

1. **OpenAI モデル** — `gpt-4o-mini` / `gpt-4o` / `o1-mini` などから選択
2. **OpenAI API キー** — `sk-...` で始まる API キー (パスワード形式で表示)
   - キーは **そのブラウザのメモリ + 該当セッションの chatbot プロセスメモリ** にのみ保持
   - リポジトリ・ログ・レスポンスには出ない
3. **Base URL (任意)** — OpenAI 互換 API を使う場合に指定
   - 空 = 公式 OpenAI (`https://api.openai.com/v1`)
   - 社内 LLM ゲートウェイ: `https://my-gw.example.com/v1`
   - LiteLLM Proxy: `http://litellm:4000/v1`
   - ローカル vLLM: `http://localhost:8000/v1`
   - 環境変数 `OPENAI_BASE_URL_DEFAULT` を仕込んでおくと初期値として入る

> 互換 API でも、SDK の仕様上 API キー欄は空にできません。認証なしのサーバならダミー
> 文字列 (例: `dummy`) を入れて回避してください。

## 4. 質問者情報

サイドバーの **「👤 質問者情報」** にログイン ID / メールアドレスを入れられる。

| 項目          | 必須か                                                      |
|---------------|-------------------------------------------------------------|
| ログイン ID   | 任意。指定すれば既存 Redmine ユーザーに紐付け               |
| メールアドレス | チャットだけなら任意。**エスカレーション時には必須**       |

ここで入れておくと、後述のエスカレーション画面で初期値として入って便利。
空でも質問は可能 (LLM で回答するだけならアカウントは要らない)。

---

## 5. 質問する

下部の入力欄に質問を書いて Enter:

```
最近のログイン失敗チケットで多い原因は?
```

AI が考え中の間「AI が考え中...」と出る。Ollama のローカルモデルだと数秒〜数十秒
かかることもあります (CPU 推論の場合は分単位)。

### 5-1. 参照チケットの確認

回答の下に **「参照チケット N 件」** という展開リンクが出る。クリックで:

```
- #123 Login fails after password reset  status=`Resolved` distance=0.213
- #98  Reset link not arriving           status=`Closed`   distance=0.297
```

- `#NNN` のリンクをクリックすると Redmine の該当チケットがブラウザで開く
- `distance` は **問い合わせ文と類似度の距離 (0 〜 2)**。**小さいほど類似**。
  - 0.0 〜 0.3: かなり関連が強い
  - 0.3 〜 0.6: ある程度関連
  - 0.6 以上: 弱い (回答も信頼度低め)
- 公開チケットのみが対象 (private は VectorDB に入っていない)

### 5-2. 続けて質問する

そのまま入力欄に追加の質問を書けば会話が続きます (直近 4 往復を LLM に渡しています)。

## 6. HITL — 解決した / 解決しない時の 3 つの選択肢

最初のメッセージを送ると、下部に 3 つのボタンが出る:

| ボタン                | 用途                                                      |
|-----------------------|-----------------------------------------------------------|
| ✅ **クローズ**       | AI の回答で解決した。セッションを閉じる                   |
| ✏️ **継続**           | (案内のみ。続きを入力欄に書けばそのまま続行)              |
| 📨 **エスカレーション** | 人 (Redmine の回答者) に依頼。チケットを起票する           |

---

## 7. エスカレーション (📨)

「📨 人にエスカレーション」ボタンを押すとポップオーバーが開く:

```
解決しなかった内容を Redmine チケットとして起票します。

メールアドレス ※必須   [               ]
チケット件名 (空ならセッション最初の発話を流用)   [        ]
☐ プライベートチケット (関係者のみ閲覧可)

[🚀 起票して人に依頼]
```

### 7-1. メールアドレスは必須

- 同じメールアドレスからの再エスカレーションは **Redmine 上で同じアカウントに名寄せ**
  されます (`sha256(email)` から派生した安定ログイン ID を使用)
- これにより「使うたびに匿名アカウントが量産される」事態を防いでいます
- 担当者からの通知メールもこのアドレスに届きます
- サイドバーに入れてあれば自動で初期値が入る

### 7-2. 件名

空のまま起票すると、セッション最初のユーザー発話 (の先頭 1 行を 255 文字に丸めたもの) が件名になります。
明示したい場合だけ入力。

### 7-3. プライベートチケット

機密な内容を「他の質問者ユーザーには見せたくない」とき ON にします。

| 立場 | 起票したプライベートチケットの見え方 |
|---|---|
| あなた自身 (起票した質問者) | ✅ Redmine UI でも閲覧・コメント可 (あなたが author だから) |
| 他の質問者ユーザー | ❌ 一覧にすら出てこない。URL を直接叩いても 403 |
| 事務局スタッフ (回答者) | ✅ 通常通り対応可 |
| システム管理者 | ✅ 通常通り対応可 |

加えて、プライベートチケットは **RAG (チャットボットの過去チケット検索) の対象
からも除外** されるため、内容が他人の質問に対する回答候補として参照されること
もありません (起票後・private のまま継続して保たれている期間)。

組織内の機密扱いの相談 (例: 個人情報を含む問い合わせ、業務上の機微な内容) の
ときだけ ON にしてください。

### 7-4. 起票完了画面

成功すると Issue 番号と次の情報が表示される:

- **Issue 番号** (例: `Issue #456`)
- **プロジェクト識別子** (例: `demo`)
- **(新規アカウントだった場合のみ)** あなたの新規ログイン ID とパスワード
  - これは **画面を閉じると二度と表示されない** 。必要ならコピーして保管
  - 同じ email で 2 回目以降のエスカレーションでは出ない (既存アカウント再利用のため)

メールアドレスにも通知が飛びます (SMTP が設定されている場合)。

---

## 8. セッションをリセット

サイドバー **「⚙️ 管理操作」** の「🔁 セッションをリセット」で:

- 現在のチャット履歴がクリアされる
- LLM プロバイダ / モデル / 質問者情報を変更可能になる

セッションは chatbot プロセスのメモリ上にあるだけなので、コンテナ再起動でも消えます。

---

## 9. ベクトル DB の更新 (crawl)

サイドバー **「⚙️ 管理操作」** の **「🔄 ベクトル DB を更新 (crawl)」** で、Redmine から
最新チケットを取り込み直す:

```
取得 9 / 新規 0 / 更新 2 / 削除 1 / スキップ(変更なし) 7 / スキップ(private) 5
```

| 項目              | 意味                                                                              |
|-------------------|-----------------------------------------------------------------------------------|
| 取得              | 公開チケットを処理した数 (= 新規 + 更新 + スキップ(変更なし))                    |
| 新規              | VectorDB に未登録 → 新たに埋め込んだ                                              |
| 更新              | `updated_on` が前回より新しい → 再埋め込みして上書き                              |
| 削除              | 公開時に取り込み済 → 今回 private 化されていた → VectorDB から削除               |
| スキップ(変更なし) | 公開のまま `updated_on` も変わっていない → 何もしない                            |
| スキップ(private) | private のまま、まだ取り込まれていない → 何もしない                              |

### 9-1. 「private 化されたチケットは消える」

例:
1. 公開チケット #42 が VectorDB に index される
2. 担当者が #42 を private に変更
3. **次回 crawl 時に** #42 が VectorDB から削除される (`削除 +1`)
4. その後 RAG で参照対象にはならない (private は除外)

「即時」ではなく「次回 crawl 時」反映の点に注意。

### 9-2. 「private が外されたら戻ってくる」

private 化されたチケットが後で public に戻されると、`updated_on` が更新されるので
通常の「新規」または「更新」パスで自動的に再 index されます。

### 9-3. 自動 crawl

`CRAWL_INTERVAL_MINUTES` を `compose.chatbot.yml` で 5 などに設定しておくと、その間隔
で自動 crawl が走ります (既定 `0` = 手動のみ)。

## 10. よくあるエラーと対処

| エラー表示                                                            | 原因                                                | 対処                                                                                          |
|-----------------------------------------------------------------------|-----------------------------------------------------|-----------------------------------------------------------------------------------------------|
| `AI 呼出失敗: HTTP 502 ... model "X" not found`                       | Ollama に未 pull のモデルを選んだ                  | `docker exec redmine-ollama ollama pull X` で pull、または ✅ のモデルを選ぶ                  |
| `AI 呼出失敗: HTTP 502 ... UnicodeEncodeError: 'ascii' codec...`      | OpenAI API キー欄に全角文字 / 不可視文字が混入     | 一度クリアして、半角 ASCII の `sk-...` を貼り直す                                            |
| `AI 呼出失敗: HTTP 502 ... AuthenticationError`                       | OpenAI API キーが間違っている / 無効               | キーを再確認、または再発行                                                                    |
| `セッション開始失敗: HTTP 422 ... OpenAI を選択した場合 llm_api_key`    | OpenAI 選んだのにキーが空                          | API キーを入力                                                                                |
| `エスカレーション失敗: ... user_email は必須`                         | エスカレーション時にメールアドレスを入れていない    | popover でメールアドレスを入力                                                                |
| `crawl 失敗: ... REDMINE_API_KEY ...`                                 | Redmine 管理者 API キー / admin 認証が未設定       | `.env` の `REDMINE_API_KEY` または `REDMINE_ADMIN_USERNAME` / `REDMINE_ADMIN_PASSWORD` を設定 |
| `参照チケットのリンクをクリックしても Redmine が開かない`              | `REDMINE_PUBLIC_URL` がブラウザから到達不能         | `.env` の `REDMINE_PUBLIC_URL` をブラウザ側から見える URL に直して chatbot を再起動           |

## 11. 仕組み (簡易)

```
[ユーザー質問]
    ↓
[Embedder: Ollama nomic-embed-text]
    ↓
[ChromaDB 検索 (top_k=5, cosine 距離)]
    ↓
[CONTEXT 整形 + システムプロンプト]
    ↓
[LLM 推論: Ollama or OpenAI互換]
    ↓
[回答 + 参照チケット (citations)]
```

### 11-1. 1 チケット = 1 ベクトル

各チケットの **件名 + Description + コメント (notes ありの journal)** を 1 つの文書として
embed しています。ステータス変更などの「notes 無し」変更ログは含めていません。

### 11-2. メタデータ

VectorDB の各エントリには以下のメタデータも保存され、RAG 結果のフィルタや citation
表示に使われます:
`issue_id` / `subject` / `project_id` / `project_identifier` / `tracker` / `status` /
`is_closed` / `priority` / `author_login` / `assigned_login` / `is_private` /
`created_on` / `updated_on` / `url`

### 11-3. システムプロンプト

LLM への指示は `chatbot/app/chain/rag.py` の `SYSTEM_PROMPT` に記述。要点:

- CONTEXT (検索結果) に書いてある情報のみ根拠にする
- CONTEXT に無ければ「過去のチケットからは判断できません。人に確認してください」と答える
- 簡潔・箇条書き優先、末尾に `参照: #N, #M` を必ず付ける

カスタマイズしたい場合はこのファイルを編集して `chatbot` コンテナを再ビルド。
